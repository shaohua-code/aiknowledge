# 项目结构与能力审计

本文记录 2026-08-13 对当前项目执行的全量结构、依赖、接口、隔离、异步任务和部署审计。代码、Alembic、OpenAPI 与根目录 `docker-compose.yml` 是事实来源。

## 1. 当前有效项目结构

```text
aiknowledge/
├── frontend/                     # 独立前端工程根目录
│   ├── apps/console/             # React 19 管理控制台
│   ├── packages/contracts/       # TypeScript 类型与 OpenAPI 快照
│   ├── packages/ui/              # 共享 UI 状态组件
│   └── infrastructure/nginx/     # 前端与 API 反向代理
├── backend/                      # 独立后端工程根目录
│   ├── services/api/             # FastAPI 控制面、运行面和领域服务
│   ├── services/worker/          # Celery Worker 镜像入口
│   ├── infrastructure/postgres/  # PostgreSQL 初始化
│   └── scripts/                  # OpenAPI 契约导出
├── docs/                         # PRD、架构、API、启动与接入说明
├── docker-compose.yml            # 当前本地完整启动入口
└── .env.example                  # Compose 配置模板
```

当前启动链路只使用以上目录：

```text
管理页面 -> frontend/apps/console/src/api -> /control/v1 -> FastAPI 领域服务
业务后端 -> /runtime/v1 -> API Key/Scope -> ApplicationContext -> 检索/回答
远程数据 -> Control API 创建任务 -> Celery Worker 抓取/解析/切片/向量化 -> PostgreSQL
```

## 3. 工程与依赖状态

- Python `*.egg-info`、mypy、Ruff、pytest、构建产物和临时测试缓存已在 `.gitignore` 中统一忽略。
- 移除未被代码使用的前端依赖 `dayjs`。
- 移除未被代码使用的后端依赖 `orjson` 与 `structlog`。
- `node_modules`、pnpm store 和 `backend/services/api/.venv` 仅用于本地开发，均被 Git 忽略。

## 4. 深度审计发现

### 4.1 启动入口唯一

根 Compose 分别使用 `frontend` 与 `backend` 作为构建上下文；pnpm 工作区完全位于 `frontend` 内，Python 工程和 Worker 完全位于 `backend` 内。

### 4.2 数据库结构与当前代码一致

当前使用单一 Alembic Head。知识、策略、轨迹等父子资源使用应用与环境复合外键；远程抓取配置使用 `sources.configuration` 和版本表。

### 4.3 远程抓取链路由 Worker 异步执行

创建远程数据源只提交任务；Worker 恢复应用与环境上下文后执行安全抓取。新版本发布成功前旧版本继续可检索。失败记录保存稳定错误码、中文原因、建议、阶段、重试次数与请求 ID。

### 4.4 自动化测试仍有空白

- 后端已有领域、隔离、安全、抓取和契约测试。
- 前端目前只有 API 错误封装测试，缺少知识接入表单、错误详情和重新抓取的组件测试。
- 当前没有 Playwright 核心流程测试。
- 真实 PostgreSQL、Redis、Celery、Docker 和外部 Provider 需要独立集成环境验证，不能由单元测试代替。

### 4.5 前端文件需要下一轮模块化

`KnowledgePage.tsx` 同时承担知识集合、文档、远程接入、运行任务和错误详情，`styles.css` 也承载全站样式。它们当前能够通过类型检查和构建，但继续增加功能前应按领域拆成组件和局部样式，降低回归风险。

### 4.6 PRD 中部分接口是目标而非现状

当前运行面已实现 `/runtime/v1/retrieve`、`/answer` 和 `/feedback`。PRD 中运行面入库、任务查询、运行面健康检查，以及工具、连接器、凭证、评测等能力仍是后续阶段，不能在对接文档中描述为已上线。

## 5. 推荐后续顺序

1. 为远程接入表单、错误详情和重新抓取补充前端组件测试。
2. 把 `KnowledgePage.tsx` 拆成集合、文档、数据源、任务和弹窗组件。
3. 增加真实 PostgreSQL/Redis/Celery 的入库集成测试和 Playwright 核心流程。
4. P1 再建设定时同步、加密凭证、业务工具和质量评测，不在现有页面内继续堆占位入口。
